# Research: building, sharing and tracking pitch decks

A small team can build this tool, but five findings change the design. **A view must never be created by the HTTP request for the link.** Microsoft documents that Safe Links scans URLs before delivery and "detonates" unknown ones in the background ([Microsoft Learn](https://learn.microsoft.com/en-us/defender-office-365/safe-links-about)), and chat apps unfurl a link as soon as it is pasted, so a view should exist only after the page's own JavaScript reports real interaction. **Access codes should be typed, not consumed by a link click**, because the same scanners burn one-time links. **Per-slide reading time is the legally sensitive layer**: it is script-based and falls under the ePrivacy consent rule on top of GDPR, while the plain "who opened what, when" log can rest on legitimate interest. Existing tools (DocSend, Papermark, Peony, Pitch) converge on a small feature core, and Papermark's own HTML viewer reports a deck as a single page, so slide instrumentation is yours to build. Link security reduces to a handful of server-side rules. Caveat: competitor comparisons and all bot-share figures are vendor claims, no AP or EDPB guidance on identified deck tracking exists, and the legal points are research, not legal advice.

## Existing tools share a small core worth copying

Every tool records a visit row (who if identified, when, duration, device, coarse location), per-page seconds and a "share of pages seen" figure. DocSend shows page-level time on its Activity tab ([Dropbox help](https://help.dropbox.com/share/dropbox-docsend-documents-activity-tab)); Papermark lists page-by-page analytics on every plan including Free ([Papermark pricing](https://www.papermark.com/pricing)). Gates are the same everywhere: an email-capture toggle, password, expiry and a disable switch. Email verification, allow lists, NDA and watermarks are the paywalled tier ([Papermark link settings](https://www.papermark.com/help/article/link-settings), [Dropbox help](https://help.dropbox.com/share/dropbox-docsend-link-settings-in-content-library)). Papermark's schema defaults are a usable template: email required on, download off, owner notification on ([link.prisma](https://raw.githubusercontent.com/mfts/papermark/main/prisma/schema/link.prisma)).

Forwarding is not detected as such by anyone. DocSend tracks forwarded visits and advises a unique link per intended recipient plus "Require email" to see who forwarded ([Dropbox help](https://help.dropbox.com/share/does-dropbox-docsend-track-visits-from-unintended-visitors)). Papermark splits cheap relational state (link, viewer, view) in Postgres from a high-volume event stream in Tinybird, with the client posting accumulated active time every 10 seconds ([page_views.datasource](https://raw.githubusercontent.com/mfts/papermark/main/lib/tinybird/datasources/page_views.datasource), [tracking-config.ts](https://github.com/papermark/papermark/blob/main/lib/tracking/tracking-config.ts)). A single Postgres table of `(view_id, slide_id, duration_ms, ts)` is enough at startup scale. Papermark renders an HTML document in a sandboxed iframe and tracks it as one page, so per-slide events must come from your own deck runtime ([html-viewer.tsx](https://raw.githubusercontent.com/mfts/papermark/main/components/view/viewer/html-viewer.tsx)). Both DocSend and Papermark default to an instant email per visit ([Dropbox help](https://help.dropbox.com/account-settings/dropbox-docsend-email-notification-settings), [Papermark help](https://www.papermark.com/help/article/email-notifications)). Papermark is AGPLv3 with a separately licensed `ee/` folder, which matters if you consider forking ([Papermark README](https://github.com/mfts/papermark)). Whether a hard email gate costs views is unproven: the "28.5 vs 4.3 visitors" figure comes from a vendor blog ([Pitchwise](https://www.pitchwise.se/blog/pitch-deck-attachment-vs-link)). The defensible default is a per-recipient token link with no gate, and email capture only on shared links.

## A GET is not a view: scanners reach links first

Safe Links scans before delivery even when URLs are not rewritten, and only the recipient's tenant admin can exempt a sender ([Microsoft Learn](https://learn.microsoft.com/en-us/defender-office-365/advanced-delivery-policy-configure)). Slack, WhatsApp, Teams and iMessage previews self-identify by user agent, security scanners generally do not, and **one vendor measured 15-40% of apparent deck views as bots** ([HummingDeck](https://hummingdeck.com/blog/why-your-deck-analytics-are-wrong)). Whether scanners execute JavaScript is not documented for Proofpoint, Mimecast or Barracuda, and sources conflict on whether Proofpoint prefetches at all, so assume it can happen. Papermark filters only self-identifying user agents ([user-agent.ts](https://github.com/papermark/papermark/blob/main/lib/utils/user-agent.ts)). DocSend flags data-center visits as "atypical" with 0.0 seconds ([Dropbox help](https://help.dropbox.com/security/dropbox-docsend-atypical-source-visits)). HubSpot, lemlist and CleverTap add timing: first hits within 2-5 seconds of sending are flagged ([lemlist](https://help.lemlist.com/en/articles/9140285-identifying-legitimate-clicks-and-opens), [CleverTap](https://docs.clevertap.com/docs/bot-activity-filter)).

The layered design that follows: serve the deck page without creating a view; create the view on the first beacon after about 3 seconds plus genuine input (a vendor-sourced rule, validate it against a Microsoft 365 test tenant); flag user-agent, datacenter-IP and send-time hits; keep flagged rows but exclude them from statistics and owner notifications, as CleverTap and DocSend do; never block IP ranges, which also hits corporate VPN users. Label the numbers "estimated human views", since even filter vendors say no filter proves a human.

For timing, flush on `visibilitychange` (hidden) with `sendBeacon`, which MDN calls the most reliable moment ([MDN](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/sendBeacon)); in a 2023 Chrome-only test about 2M page views delivered **95.8% of beacons** ([Nic Jansma](https://nicj.net/beaconing-in-practice-an-update-on-reliability-and-the-pending-beacon-api/)). Heartbeat every 10 seconds and on each slide change so a killed mobile tab loses seconds, not the session. Accumulate time from timestamp deltas, not timer ticks, because background tabs throttle timers ([MDN](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)). Papermark's `duration` is unbounded server-side; give events client ids and cap each segment by the time since the previous flush. Key events by an immutable `slide_id` plus `deck_version`, because position-keyed history misleads after edits ([HummingDeck help](https://hummingdeck.com/support/replace-document-without-changing-links)).

## Send a typed code from an EU-hosted, tracking-free sender

Scanners can invalidate one-time magic links before the human clicks, as Stytch, Descope and Vanta document ([Stytch](https://stytch.com/products/email-magic-links), [Descope](https://docs.descope.com/flows/use-cases/email-scanner), [Vanta](https://status.vanta.com/incidents/8zx3jd1kjq5w)); no Microsoft or Proofpoint page says so directly. A typed code avoids the problem. NIST SP 800-63B-4 gives the parameters: at least six digits, 10 minutes, single use, and a new code must not reset the failed-attempt counter ([NIST](https://pages.nist.gov/800-63-4/sp800-63b.html)). With 5 attempts per code a blind guess succeeds with probability 5 in 1,000,000 (my arithmetic), so count failures per recipient and deck, not only per IP. NIST says email should not be used for out-of-band authentication, but an access gate on a deck is lower stakes, so treat it as a parameter benchmark and record the decision. If invitees are known, send codes only to invited addresses, which removes the mail-bomb vector.

Below Gmail's 5,000-per-day bulk threshold only SPF or DKIM is formally required, but Google recommends all three and is "ramping up" enforcement ([Google sender guidelines](https://support.google.com/a/answer/81126), [FAQ](https://support.google.com/a/answer/14229414)). Publish SPF, 2048-bit DKIM and DMARC `p=none` with `rua` on a dedicated sending subdomain. Turn provider click and open tracking off: it rewrites your links through the provider's redirect domain and stores per-click location ([Postmark](https://postmarkapp.com/developer/user-guide/tracking-links)), and Lettermint advises off for security mail ([checklist](https://lettermint.co/docs/production-checklist)). Send multipart mail with no remote images and no unsubscribe header (transactional mail is exempt). HTML-escape every submitter-supplied value in team notifications ([Twilio](https://www.twilio.com/en-us/blog/dont-get-pwned-via-email-html-injection)). For EU data, Scaleway TEM (Paris, 300 free mails a month then EUR 0.25 per 1,000) and Lettermint (Dutch, EUR 10 for 10,000) fit; Mailgun binds message data to an EU region ([Scaleway](https://www.scaleway.com/en/docs/transactional-email/reference-content/data-privacy/), [Lettermint](https://lettermint.co), [Mailgun](https://documentation.mailgun.com/docs/mailgun/api-reference/api-overview)). Postmark has no EU servers and Resend's EU region covers sending only ([Postmark](https://postmarkapp.com/euprivacy), [Resend](https://resend.com/security/gdpr)). Avoid 100-per-day free tiers for time-critical codes, and test inboxes at Gmail, Outlook.com and a Safe Links-protected tenant before launch. Scaleway facts come from search excerpts, and current Microsoft enforcement for small senders is unconfirmed.

## Per-slide timing leans on consent, the open log on legitimate interest

The Telecommunications Act art. 11.7a applies on top of GDPR: storing or reading information on a user's device needs consent unless strictly necessary, or low-impact service-quality measurement ([wetten.overheid.nl](https://wetten.overheid.nl/BWBR0009950/2026-08-15)). EDPB Guidelines 2/2023 treat script-produced data sent back to a server as "gaining access" (para 53) ([EDPB](https://edpb.europa.eu/system/files/2024-10/edpb_guidelines_202302_technical_scope_art_53_eprivacydirective_v2_en_0.pdf)). Per-person reading time mainly serves the sender, so I read it as outside the exemption (uncertain; no AP or court ruling on this fact pattern). The server-side record that an identified person opened a link has a plausible legitimate-interest basis, needing a written balancing test ([EDPB 1/2024 consultation](https://www.edpb.europa.eu/our-work-tools/documents/public-consultations/2024/guidelines-12024-processing-personal-data-based_nl?page=5)). The cautious design is an unticked, logged choice on the gate with a "view without reading-time tracking" path, since the AP rejects cookie walls ([Telecompaper](https://www.telecompaper.com/nieuws/ap-cookiemuur-is-overtreding-van-avg--1283730)). Putting a tracking pixel in the invitation is worse: EDPB and the CNIL's 2026 recommendation both put pixels under consent ([CNIL](https://www.cnil.fr/sites/default/files/2026-04/recommandation-pixels_de_suivi.pdf)). The Digital Omnibus would exempt only aggregate measurement and is not law ([ppc.land](https://ppc.land/digital-omnibus/)).

Operationally: the gate session cookie is exempt but still mentioned in the notice ([Ondernemersplein](https://ondernemersplein.overheid.nl/wetten-en-regels/gebruik-van-cookies-op-uw-website/)). Show the art. 13 notice before any beacon fires, give a separate objection route under art. 21(4), and if the sender uploads the viewer's email, send the notice with the invitation under art. 14 ([art. 13](https://gdpr-info.eu/art-13-gdpr/), [art. 14](https://gdpr-info.eu/art-14-gdpr/), [art. 21](https://gdpr-info.eu/art-21-gdpr/)). Self-host fonts, scripts and video: a Munich court held that loading Google Fonts without consent unlawfully sent visitor IPs to Google ([LG München I](https://gwern.net/doc/www/rewis.io/349d376d95f9b44a7e8119b1408f382e6f19938b.html), first-instance, not binding in NL). Store a coarse device class instead of the user agent, and keep IPs out of the event table. The AP sets no retention period, so choose one per table and write it down ([AP](https://www.autoriteitpersoonsgegevens.nl/en/themes/basic-gdpr/privacy-and-personal-data/retention-of-personal-data)). Hashing an email does not anonymise it for the holder of the table ([recital 26](https://gdpr-info.eu/recitals/no-26/)), and a soft-delete flag is not erasure, so erasure must null the identifying columns.

## Treat the link as a credential and gate every byte

Use 16 random bytes (128 bits) from a CSPRNG, base64url-encoded, never sequential IDs; OWASP's 128-bit figure is written for session tokens and applied here by analogy ([OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)). Only a server-side gate protects content: anything sent before verification is readable in the network tab, so slides, PDF and video must come through a route that checks the same session, with deny-by-default ([OWASP A01](https://top10.owasp.org/2021/A01_2021-Broken_Access_Control)). Send `Cache-Control: no-store`, `Referrer-Policy: no-referrer` and `X-Robots-Tag: noindex, nofollow` on every gated response including assets ([OWASP HTTP Headers](https://cheatsheetseries.owasp.org/cheatsheets/HTTP_Headers_Cheat_Sheet.html)). Do not Disallow share paths in robots.txt, because Google then never sees the noindex ([Google](https://developers.google.com/search/docs/crawling-indexing/block-indexing)). Serve neutral Open Graph data on the pre-auth page, never the deck title, since unfurlers read it. Use one `__Host-` session cookie (Secure, HttpOnly, SameSite=Lax) plus a server-side list of authorised links. Keep rate-limit counters in a shared store such as Redis keyed by link and normalised email, with growing delays instead of permanent lockout, which would let an attacker lock investors out ([OWASP Authentication](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)). Gating stops unauthorised access, not screenshots or onward sharing by an authorised viewer, and the product should say so.

## What the best decks and runtimes teach

**Story.** Sequoia's outline runs purpose, problem, solution, why now, market, competition, business model, team, financials, vision ([Sequoia](https://sequoiacap.com/article/writing-a-business-plan)). YC's seed deck advice adds traction early and ends on the ask ([YC library](https://ycombinator.com/library/2u-how-to-build-your-seed-round-pitch-deck); order from a [secondary summary](https://medium.com/small-business-insights/how-to-create-the-perfect-pitch-deck-30e220027993)). Kevin Hale's rule for every slide is legible, simple and obvious: large bold type, one idea, the conclusion written on the chart, and screenshots avoided because they are "almost always illegible" ([YC](https://www.ycombinator.com/blog/how-to-design-a-better-pitch-deck)). Kawasaki's 10/20/30 sets 10 slides, 20 minutes and no font under 30 pt ([CBS](https://www.cbsnews.com/news/improve-your-powerpoint-presentations-with-guy-kawasakis-10-20-30-rule/)). Reid Hoffman calls the risk slide his LinkedIn deck lacked essential ([Hoffman](https://www.reidhoffman.org/linkedin-pitch-to-greylock/)).

**Reading time (DocSend, vendor data).** Investors spent just under 3 minutes per deck in 2022, 24% less than before; product and business model were the most viewed; every deck had a team slide; none of the failed decks had financials ([TechCrunch](https://techcrunch.com/2022/09/22/science-of-pitch-decks/amp)). In 2019 successful decks averaged 20 pages against 17 for failed ones, and failed decks lost a minute on an opening product page ([TechCrunch](https://techcrunch.com/2019/04/12/data-tells-us-that-investors-love-a-good-story)).

**Runtime.** reveal.js (MIT, since 2011, 6.x in 2026) ships keyboard navigation, swipe, edge controls, progress, slide numbers, `#/id` deep links, an overview, a speaker view with timing, a print view for PDF, a scroll view at phone width and a `slidechanged` event ([config](https://revealjs.com/config/), [links](https://revealjs.com/links/), [speaker view](https://revealjs.com/speaker-view/), [PDF](https://revealjs.com/pdf-export/), [scroll view](https://revealjs.com/scroll-view/), [events](https://revealjs.com/events/)). It mounts inside an app with `embedded: true` and `destroy()` ([initialization](https://revealjs.com/initialization/)). Speaker notes stay in the page source, so a viewer build must leave them out ([speaker view](https://revealjs.com/speaker-view/)). Slidev (MIT) builds one Vite app per deck with a base path fixed at build time and numbered routes, so it fits a markdown-in-git workflow better than an app that serves many links ([hosting](https://sli.dev/guide/hosting)). No reduced-motion handling was found in reveal's source, so the app sets transitions off itself. Pitch records engagement only after the visitor accepts a consent popover ([Pitch help](https://help.pitch.com/en/articles/5592127)).

## Conclusion

*Since settled in the plan:* the code mail goes only to the address on the link; nothing is logged per viewer without consent; the mail provider is a choice per startup; erasure is a hard delete.

The three hard choices (typed code, no pixel in mail, consent-gated timing) all push the same way: the gate page, not the mail or the HTTP request, is the single place where identity, consent and the first trusted interaction meet, and a "view" is a derived, qualified record rather than a logged event. That is also where this tool can beat the incumbents, since Papermark's HTML path tracks one page and its documented bot filter stops at user agents.

Four decisions remain with the owner: whether recipients may type any address or only invited ones, consent versus legitimate interest for reading time (ideally confirmed by a privacy lawyer or the AP, together with whether a per-recipient URL counts as a "tracking link"), the mail provider, and an explicit anonymise-then-delete routine that reconciles a soft-delete policy with erasure. Untested assumptions are the 3-second interaction gate, the Chrome-only beacon figure on iOS Safari, and scanner JavaScript execution; a Microsoft 365 test tenant with Safe Links on settles the last two.
